# 💼 China Career Board (china-jobs) — Agent Guide

This repository is the **Careers and Job Board** sub-app of the China Suite ecosystem. It is a client-side React SPA that aggregates professional job listings (primarily technical and engineering roles) across China, Hong Kong, Singapore, and Sweden, and provides an offline applicant tracking dashboard.

---

## 🎯 What this project does

- **Job aggregation**: Displays active job listings fetched from dozens of company career sites and ATS platforms.
- **Search & filtering**: Filter jobs by region, company, search term, and "new since last visit".
- **Saved views**: Star jobs, hide jobs, and browse a history of removed listings.
- **Company directory**: Browse tracked employers with descriptions, office locations, and active role counts.
- **Applicant Tracking System (ATS)**: Track application status, interview stage, recruiter contacts, and notes for any job or custom external role.
- **Data portability**: Export/import local session data (stars, hidden jobs, tracked applications, custom jobs, theme) via JSON backup files.
- **Theme sync**: Dark/light mode is persisted to `localStorage` under the key `theme` and synced with sibling China Suite apps via the shared `china-common` package.

## 🧭 Routing & views

`App.tsx` uses `HashRouter` with the following routes:

| Route | Component | Purpose |
|-------|-----------|---------|
| `/` | `JobsView` | Active job listings |
| `/starred` | `JobsView` | Starred jobs |
| `/history` | `JobsView` | Removed listings + hidden listings recovery |
| `/companies` | `CompaniesView` | Company directory |
| `/applications` | `ApplicationsView` | ATS dashboard |
| `/settings` | `SettingsView` | Backup, restore, reset local data |
| `*` | `Navigate` | Redirect to `/` |

`Header.tsx` provides top navigation tabs and a global search bar. The `SuiteSwitcher` from `china-common` cross-links the other China Suite apps.

## 💾 State management & localStorage

All user state is client-side and persisted to `localStorage`. There is no backend database.

| localStorage key | Content |
|------------------|---------|
| `seen_job_ids` | IDs of jobs the user has already viewed |
| `starred_job_ids` | IDs of starred jobs |
| `hidden_job_ids` | IDs of jobs hidden from active/history feeds |
| `applied_jobs_data` | Map of `jobId -> JobApplication` |
| `custom_jobs_data` | Map of `jobId -> Job` for manually tracked external roles |
| `all_ever_seen_jobs` | Cache of every job the app has ever loaded (pruned after 180 days unless active/starred/tracked) |
| `theme` | `"dark"` or `"light"` |

The `useJobs()` hook in `src/hooks/useJobs.ts` is the single source of truth for:
- Fetching `public/jobs.json`
- Deriving `removedJobs` (previously seen but no longer active)
- Managing stars, hidden jobs, and applications
- Adding custom jobs for external roles

`useTheme()` reads/writes the `theme` key and toggles the `.dark` class and `color-scheme` style on `document.documentElement`.

## 📦 Data model

Defined in `src/types/index.ts`:

```ts
interface Job {
  id: string;            // platform-prefixed, e.g. "gh-12345", "sh-J00000000"
  title: string;
  company: string;
  location: string;
  link: string;          // external application URL
  postedAt: string;      // ISO date string
  region: string;        // China, Hong Kong, Singapore, Sweden, or Other
}

interface CompanyInfo {
  name: string;
  description: string;
  regions: string[];
  offices: string[];
  careerUrl: string;
  logoDomain: string;    // used with Clearbit Logo API
  customLogo?: string;   // optional local filename in public/
}

interface JobApplication {
  jobId: string;
  status: 'applied' | 'interviewing' | 'offer' | 'rejected' | 'withdrawn';
  appliedAt: string;
  contactName?: string;
  contactEmail?: string;
  processStep?: string;
  notes?: string;
  updatedAt: string;
}
```

## 🤖 Job scraper & data pipeline

- `scripts/fetch_jobs.js` queries ~50+ company career platforms (Greenhouse, Ashby, SmartRecruiters, Workday, Oracle HCM, Algolia, Phenom, RMK/SuccessFactors, internal APIs, XML feeds, etc.).
- It filters results by region (`China`, `Hong Kong`, `Singapore`, `Sweden`) and by a keyword list in `scripts/fetch_jobs.js`.
- Output is written to `public/jobs.json`.
- `.github/workflows/update_jobs.yml` runs the scraper daily at midnight UTC and commits changes to `main` if `public/jobs.json` changed. Its pushes use `GITHUB_TOKEN`, which does not trigger `push`-based workflows, so `deploy.yml` instead redeploys via a `workflow_run` trigger on "Update Job Listings" completion.
- **Do not edit `public/jobs.json` manually** — it is regenerated by the scraper.

## 🎨 Code style guidelines

- **Imports**: Use `import type { Foo }` for type-only imports. `verbatimModuleSyntax: true` enforces this.
- **Components**: Functional components with an explicit `interface *Props` above the function.
- **File naming**: PascalCase for components (`JobCard.tsx`), camelCase for hooks (`useJobs.ts`), kebab-case for workflows.
- **Styling**: Tailwind utility classes only. Dark-mode variants use the `.dark` class strategy (`dark:bg-slate-900`).
- **Colors**: Blues (`blue-600`) for primary actions, amber for stars, purple for companies, green for offers, red for rejected/closed.
- **Icons**: Use `lucide-react` consistently.
- **String literals**: Prefer single quotes in TSX/TS unless double quotes are required.
- **Accessibility**: Buttons include `aria-label` and `title` attributes.

## 🔒 Security considerations

- **No server-side code**: Everything runs in the browser. No API keys or secrets are exposed to users except those already present in the public scraper script (intended for CI only).
- **localStorage**: User data never leaves the browser unless explicitly exported by the user in `SettingsView`.
- **External links**: Job cards open company career sites in a new tab with `rel="noopener noreferrer"`.
- **Scraper**: `scripts/fetch_jobs.js` runs only in GitHub Actions and writes to a public JSON file. It does not authenticate against private APIs.
- **XSS**: Avoid rendering raw HTML from job data. The app currently renders text content safely.

## 📝 Common agent tasks

- **Add a new tracked company**: Update `src/constants/companies.ts` and add the corresponding scraper logic in `scripts/fetch_jobs.js`.
- **Add or change regions**: Update `src/constants/regions.ts`, the region detection logic in `scripts/fetch_jobs.js`, and any region filter UI.
- **Change application statuses**: Update `JobApplication['status']` in `src/types/index.ts`, then update `ApplicationModal.tsx`, `ApplicationsView.tsx`, and `JobCard.tsx` badge styling.
- **Add a new localStorage key**: Mirror the pattern in `useJobs.ts` (load in initial state, persist on change, prune/reset in `SettingsView.tsx`).
- **Update scraper keywords or companies**: Edit `scripts/fetch_jobs.js` and run `node scripts/fetch_jobs.js` locally to regenerate `public/jobs.json`.

## ⚠️ Things to be aware of

- `public/jobs.json` is machine-generated. Manual edits will be overwritten by the daily scraper workflow.
- The scraper targets third-party career APIs and HTML structures; integrations can break silently when those sites change. Failures are swallowed and logged to keep the workflow from blocking the build.
- `App.tsx` passes a large props surface down to `JobsView`. Keep prop drilling in mind when adding new global filters.
- The app assumes it is served from `/china-jobs/`; changing `vite.config.ts` `base` requires matching updates to `public/manifest.json` and the GitHub Pages settings.
